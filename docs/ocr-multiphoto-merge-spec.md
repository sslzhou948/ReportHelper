# OCR Multi-photo Merge Spec

Updated: 2026-05-30

本文档定义“多张照片描述同一份检查报告”的识别、拼接、去重和冲突处理规则。该能力服务于用户在上传页手动绑定报告组的场景，也为未来系统自动提示疑似合并保留接口空间。

## 1. Scope

多图合并适用于：

- 报告换页后分多张照片拍摄。
- 手机截图空间有限，同一报告被截成多段。
- 长表格的页尾和下一页页头存在重复行。
- 报告基础信息只出现在第一页或最后一页。
- 同一批上传中同时包含单页报告和多页报告。

不在 MVP 自动处理、但要预留检测：

- 用户未绑定但系统怀疑多张图片属于同一报告。
- 一张图片中包含两份独立报告。
- 用户错误绑定了不同报告。

## 2. Group Contract

上传页的 `groupId` 是用户显式分组信号：

- 一个 `groupId` 表示用户期望生成一份报告草稿。
- 同组图片按 `sortOrder` 作为页序。
- 同组图片识别后默认输出一份 `OcrDraft`。
- `sourcePhotoIds` 必须包含组内所有图片。
- `pageCount` 必须等于组内图片数量。
- OCR evidence 必须保留每张图片的页序、原文、表格块、行级证据和置信度。

如果 provider 明确发现同组中存在两份独立报告，不应静默合并；应返回 warning/conflict，MVP 让用户返回上传页重新分组。

## 3. Merge Rules

基础信息合并：

- 医院、患者、申请日期、报告类型优先取第一页。
- 第一页缺失时，可从同组后续页补齐。
- 从后续页或同组推断补齐的字段必须标记来源。
- 同组字段冲突时，不自动选择，返回 `MULTIPAGE_INCONSISTENT`。

正文合并：

- 按页序拼接表格行和描述文本。
- 去掉重复页眉、页脚、表头、医院名称、报告标题和说明文字。
- 跨页断裂的表格行可以基于行序、列名和邻近文本合并。
- 无法确定是否断裂时保留 warning，不编造缺失值。

实验室指标去重：

- `metricKey + value + unit + refText/refRange + tone` 一致：保留一条。
- `originalMetricName + value + unit + refText` 一致但 metricKey 不一致：进入 mapping conflict。
- `metricKey` 一致但 value 不一致：进入 value conflict，禁止直接保存。
- 历史对比列、上次结果、前次结果不作为本次结果入库。
- 左侧重点标记只作为 report marker，不作为偏高偏低。

影像、病理和电生理内容去重：

- 按页序合并 findings。
- 重复的标题、检查部位、影像所见标题、诊断意见标题应去重。
- 不同部位或不同检查方法不能因为报告名称相同而合并为同一条结论。

## 4. Wrong Binding Detection

以下情况应判定为疑似错误绑定：

- 同组图片医院明显不同。
- 同组图片患者姓名明显不同。
- 同组图片申请日期或检查日期明显冲突。
- 同组图片报告类型不兼容，例如血常规和 CT 报告。
- 同组图片出现两个完整且互不相干的报告抬头。
- 同一指标在同一报告中出现冲突结果，且不像历史对比列。

MVP 行为：

- 确认页显示冲突。
- 保存按钮不可直接提交。
- 用户返回上传页重新分组，或后续在确认页拆分。

## 5. Missing Binding Hint

如果用户忘记绑定，系统未来可以提示，但 MVP 不自动合并：

- 同批相邻图片医院、患者、日期、报告类型相同。
- 一张图底部和另一张图顶部存在重复表头或连续指标。
- 图片存在页码或报告编号连续关系。
- 两张图片单独识别都像不完整报告。

提示文案应偏保守，例如“这几张图片可能属于同一份报告，是否返回上传页合并？”。

## 6. Acceptance Cases

必须覆盖的测试基线：

- 4 张图，其中 1+2 绑定，最终生成 3 份草稿。
- 2 张同报告图片，页眉和表头重复，最终生成 1 份草稿且重复行只保留一次。
- 2 张同报告图片，基础信息第一页缺失、第二页存在，最终补齐并标记来源。
- 2 张错误绑定图片，报告类型冲突，返回 `MULTIPAGE_INCONSISTENT`。
- 2 张同报告图片，同一指标值冲突，返回 conflict。
- 报告含本次/上次两列，只保存本次结果。
- 影像报告多页 findings 按页序合并，不进入指标趋势。

## 7. Risk Control

多图合并的最大风险不是漏合并，而是错合并。因此默认策略应保守：

- 用户显式绑定优先，但绑定结果仍要做一致性检查。
- 系统自动识别疑似合并只能提示，不应静默改变用户分组。
- 结果值冲突必须让用户确认。
- 无法确定的内容宁可进入 warning，也不要补成看似完整的错误报告。

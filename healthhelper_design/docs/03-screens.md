# 页面交互详解

> 本文档为每个页面定义视觉结构、状态、交互行为、跳转目标。视觉效果以 `wireframes/我的病例夹 线框稿.html` 为准。

---

## 边界场景与处理（重要）

> 这一节集中说明几个真实场景下的特殊处理。开发时必须严格遵守。

### E1. 不同医院的参考范围不同

详见 docs/05-data-model.md 第 2.5.2 节。
- 存储：按每次报告的原始参考范围存
- 异常判断：按该次报告自己的参考范围
- 曲线图：单条参考线（最新一次），不画色带
- 历史记录每行显示具体参考范围

### E2. 未知指标 / 同义词 / 分类冲突

详见 docs/05-data-model.md 第 2.5.3 节。
- OCR 识别后优先匹配 aliases 列表
- 完全不认识的指标：根据报告栏目自动建议归类，用户可调整
- 该指标以 status: pending 入库，等管理员审核
- 跨医院分类冲突：首次入库为准，后续保持稳定

### E3. 后台识别期间切换档案

- 识别任务属于发起时的档案，不跟随当前选中档案变化
- 首页悬浮条仍显示识别中
- 点击悬浮条进入的确认页，绑定的是任务发起时的档案
- 完成后通知到用户：通知点击直接打开对应档案的确认页（自动切换档案）

### E4. 多个识别任务并发

- 首页悬浮条显示"识别中（2 个任务）"
- 点击展开列表，每个任务一行
- 完成的任务变成"请确认"状态

### E5. 当前档案被删除

- 自动选第一个剩余档案，更新 lastProfileId
- 如果一个档案都没了，跳 ⑤ A 重新创建

### E6. 定性型指标（阴性 / 阳性）

详见 docs/03-screens.md 第 3.2.2 节。
- 不显示曲线
- 历史列表用色块 pill 标注结果
- 提示条说明"此项为定性指标，结果为阴性 / 阳性，不显示趋势曲线"

### E7. 同月多次检查 + 真实日期映射的取舍

- 曲线图 X 轴**不按真实日期映射**，数据点等距分布
- X 轴标签显示真实日期
- 当数据点 > 6 时，曲线区域横向滚动
- 历史记录列表保持真实日期顺序，用户想看精确时间往下看

### E8. OCR 完全失败

- 失败的图在 Step 3 确认页显示为单独的卡片"未识别到内容"
- 提供"手动填写"入口 → 进入 Step 4 编辑详情（所有字段为空）

### E9. OCR 部分成功 / 不确定项

- 在 Step 4 编辑详情页，OCR 置信度低的行用黄色高亮 + `!` 图标
- 提示用户重点检查这些行

### E10. 合并多页的报告基本信息不一致

- 用户用曲别针把图 1 + 图 2 合并为一份报告
- 但 OCR 识别出两张图的医院 / 日期 / 类型不同
- Step 3 确认页弹提示："这几张图的基本信息不同，确认合并吗？"
- 用户确认后，以第一张为准；可在 Step 4 手动修改

### E11. 合并时的指标冲突

- 同 metricKey + 同值 → 静默去重
- 同 metricKey + 不同值 → 标记冲突
- Step 3 卡片显示橙色"X 项重复识别"
- 必须处理完所有冲突，"全部保存到病例夹"按钮才可点击

## 1. 首页 / 工作台 — `pages/home/index`

3 种状态根据登录态 + 数据量切换。

### 1.1 状态 A：未登录

**触发条件**：未授权微信登录，或登录态过期。

**结构（从上到下）**：

1. 顶部绿色渐变 banner（高 280px）
   - 居中：App 图标 + 标题"我的病例夹" + 副标题"电子病例夹 · 公益免费"
2. 中部文案：
   - "轻松管理检查报告"
   - "追踪健康指标，规划复查日程"
3. 底部固定区域（距底 60px）：
   - **主按钮**：微信一键登录（高 48px）
   - 协议提示："登录即同意《用户协议》和《隐私政策》"

**交互**：

| 元素 | 行为 |
|------|------|
| 微信一键登录按钮 | 调用 `wx.login()` → 后端换取 openid + token → 写入 localStorage → 跳转到 home 状态 B 或 C |
| 用户协议链接 | 打开 H5 / 内嵌 webview |
| 隐私政策链接 | 同上 |

**异常处理**：

- 用户拒绝授权：保持在状态 A，但显示 toast"未授权将无法使用"
- 网络失败：按钮置为 loading，5s 超时显示重试

---

### 1.2 状态 B：已登录，无数据

**触发条件**：登录后 `reports` 数量为 0。

**结构**：

1. 顶部 banner（高 150px）
   - "早上好，{用户昵称}"
   - 副："{今天日期} · {星期}"
2. 中部插画区域（约 140px 高的占位图，用户没数据的空状态）
3. 中部文案：
   - "还没有检查报告"
   - "上传一份开始管理你的健康指标"
4. **主按钮**：上传第一份报告
5. 提示："支持血常规、肝功能、CT 报告等"
6. 底部 TabBar

**交互**：

| 元素 | 行为 |
|------|------|
| 上传第一份报告 | `wx.navigateTo` → `pages/upload/index` |
| TabBar 切到健康数据 / 复查 / 我的 | 均显示对应 Tab 的空状态版本 |

---

### 1.3 状态 C：已登录，有数据

**触发条件**：`reports.length > 0`。

**结构（从上到下，可滚动）**：

1. **顶部 banner**（高 140px）
   - 左：问候语"早上好，{昵称}" + 副"愿你今天舒心"
   - 右：圆形头像（点击跳"我的"Tab）
2. **上传 CTA**（主色背景大卡片）
   - 标题"上传检查报告"
   - 副"拍照 / 相册 · AI 自动识别"
3. **复查提醒卡**（白底卡片）
   - "距下次复查还有 {n} 天"
   - 副"{日期} · {医院} · {类型}"
   - 点击 → 复查 Tab
4. **关注指标横滑**（最多 4-5 张 mini 卡片）
   - 每张：指标名 / 数值 / mini sparkline
   - "管理 ›" 链接打开"哪些指标显示在首页"设置
   - 点击单张 → 指标详情
   - **[需确认]**：关注指标是用户主动收藏，还是系统推荐异常项 + 用户最常看的混合算法？
5. **最近报告**（最多 3 条）
   - 报告类型 / 医院 / 日期 / 异常数标识
   - 点击 → 报告详情
   - "查看全部 ›" → 健康数据·按时间
6. **异常预警卡**（仅当有异常时显示）
   - 红色左边条
   - "最近 X 项指标偏离正常"
   - 列出异常指标 pill，点击 → 指标详情
7. 底部 TabBar

**交互**：

| 元素 | 行为 |
|------|------|
| 上传 CTA | `wx.navigateTo` → upload |
| 头像 | `wx.switchTab` → profile（**[需确认：是否切 Tab，还是 navigateTo 不显示 TabBar]**） |
| 关注指标卡 | `wx.navigateTo` → metric-detail |
| 报告卡 | `wx.navigateTo` → report-detail |
| 复查提醒卡 | `wx.switchTab` → recheck |

**状态变化**：

- 下拉刷新：重新拉取报告/指标/复查数据
- 数据更新时局部刷新（不闪屏）

## 2. 健康数据 Tab — `pages/health/index`

### 2.1 通用结构

```
┌─ 顶部 NavBar：标题"健康数据"，右上"上传"
├─ 搜索框（不可输入，仅作为入口，点击进搜索页 [需确认]）
├─ Segmented control：[按指标 48 项 | 按时间 12 份报告]
├─ 时间范围：[近30天 | 近90天 | 近1年 | 全部]（默认近30天）
├─ ┌─ 按指标视图 ───────────┐ 或 ┌─ 按时间视图 ──────────┐
│  │ chip 筛选行            │    │ 月份分组的报告列表    │
│  │ 折叠主题分组的指标列表 │    │                       │
│  └────────────────────────┘    └───────────────────────┘
└─ 底部 TabBar
```

**默认切到"按指标"，默认时间范围为近 30 天。**

**时间范围口径**：
- `按指标`：只统计所选时间范围内有记录的指标，异常数是“当前范围内最新值仍异常的指标数”。
- `按时间`：只展示所选时间范围内的报告，异常数是“各报告异常结果项合计”。
- 两个视图的异常数字不强求相等，必须在界面文案上区分“异常指标”和“异常项”。

### 2.2 按指标视图

**chip 筛选行**（横向滚动）：
- `全部` / `异常指标 ●3` / `血常规` / `肝功能` / `肾功能` / `肿瘤标志物` / ...
- 单选，点击切换；"异常指标"上的小红点显示所选时间范围内的异常指标总数
- chip 列表由后端返回，主题按"含异常的优先 + 用户常看的优先"排序

**主题分组**（每组一张卡片）：

```
血常规 ▼ 12 项 · 1 异常 · 最近 4·28
  ├─ 白细胞     3.2 ↓    2 天前 · ↘ 持续下降   →
  ├─ 血红蛋白   128       2 天前 · → 平稳        →
  ├─ 血小板     189       2 天前 · ↗ 略上升      →
  └─ 展开剩余 9 项 ▾
```

**指标行字段说明**：

| 字段 | 来源 | 说明 |
|------|------|------|
| 指标名 | metric.name | 中文为主，可显示英文缩写（如 ALT） |
| 数值 | metric.lastValue | 异常时染色（高=玫瑰红，低=灰蓝） |
| 异常箭头 | metric.lastTone | `↑` 偏高、`↓` 偏低 |
| 时间戳 | metric.lastDate → 相对时间 | 当天="今天"，>30 天显示"X 月前" |
| 趋势文字 | 基于最近 3 次的值 | "持续上升 / 略上升 / 平稳 / 略下降 / 持续下降" — **[需确认算法]** |
| 进入箭头 | — | 必须，提示可点击 |

**折叠规则**：

| 主题状态 | 默认 |
|---------|------|
| 含异常 | 展开（显示前 3 项 + "展开剩余"按钮） |
| 全部正常 | 折叠（仅显示主题头） |

**最近时间显示规则**：

- 主题最近一次检查 ≤ 30 天：正常灰色
- 30-90 天：仍灰色但右侧补"较旧"提示
- > 90 天：暖橙色 + ⚠ 图标

**首次进入引导**：

- 用户首次进入"按指标"视图，浮一个气泡："👆 点击任意指标，查看完整曲线和历次详情"
- 点击关闭按钮（×）或 3 秒后自动消失
- 用 localStorage 记 `hint.health.metricRow = dismissed`，不再显示

**交互**：

| 元素 | 行为 |
|------|------|
| 搜索框 | `wx.navigateTo` → search 页 **[需确认：是否独立页面]** |
| chip | 单选切换，触发本地过滤；不需要请求后端（指标列表全量加载） |
| 主题头 | 点击切换折叠/展开 |
| 指标行 | `wx.navigateTo` → metric-detail?metricKey={key} |
| "展开剩余" | 原地展开 |
| 右上"上传" | `wx.navigateTo` → upload |
| 气泡引导 | 点击 × / 3s 自动消失 |

### 3.2 指标详情 — `pages/health/metric-detail`

**URL 参数**：`metricKey={key}`

**两种渲染模式**（根据 `metric.type` 自动判断）：

#### 3.2.1 数值型（quantitative）

适用：白细胞、血红蛋白、CEA、ALT 等所有有具体数值的指标。

**结构**：

1. NavBar：标题为指标中文名
2. **顶部数值卡**：
   - 大字数值（44px，异常染色）+ 单位
   - 异常 pill（↓ 偏低 / ↑ 偏高 / 正常）
   - 参考范围 pill
   - 最近一次数据来源："4 月 28 日 · 协和医院"
3. **趋势曲线卡**：
   - 标题"趋势"
   - 当数据点 > 6 时右上角提示"← 滑动查看更早 →"
   - SVG 曲线图：
     - Y 轴：3-4 个刻度，横向虚网格线
     - 参考范围色带（绿色背景）
     - 参考线（虚线 + 数值标签）
     - 数据点等距分布（**不是按真实日期映射**），X 轴标签显示真实日期
     - 当前点（最右）半径 5px，历史点半径 3.5px
     - 异常点用异常色，正常点用主色
   - 当数据点 > 6 时，**曲线区域横向可滚动**
4. **历史记录列表**：
   - 标题"历史记录" + 右上"X 次"
   - 每行：日期 / 年份 / 数值（异常染色） / 进入箭头
   - 不显示医院名（节省空间）
   - 提示文本"点击任意行，跳转到该次报告详情"
5. 整个页面可滚动

**交互**：

| 元素 | 行为 |
|------|------|
| 历史记录每行 | `wx.navigateTo` → report-detail?id={row.reportId} |
| 曲线图 | 横向滚动 |

#### 3.2.2 定性型（qualitative）

适用：乙肝两对半（HBsAg）、HIV 抗体、HCG 阳性/阴性等结果只有"阴性 / 阳性 / +/++/+++"的指标。

**结构**：

1. NavBar
2. **顶部数值卡**（不再大字数值，改用文字）：
   - 大字"阴性"
   - 正常 pill
   - 参考"阴性"
   - 最近来源
3. **不显示曲线**，替换为提示条：
   - 浅黄色背景的提示："此项为定性指标，结果为阴性 / 阳性，不显示趋势曲线"
4. **历史记录列表**：
   - 每行：日期 / 年份 / **结果 pill**（阴性=绿，阳性=红） / 进入箭头

**渲染逻辑**：


## 6. 上传流程 — `pages/upload/*`

> **注意**：当前线框稿**没有**上传流程的页面，本节为基于 PRD 和讨论的设计建议，需用户最终确认。

### 6.1 步骤 1：拍照 / 选图 — `pages/upload/index`

**结构**：

- 顶部说明："拍照或选择检查报告，AI 会自动识别"
- 大按钮：
  - 📷 拍照
  - 🖼 从相册选择（支持多选）
- 已选图片缩略图列表（可删除单张、可继续添加）
- 底部主按钮"识别"（仅当已选 ≥ 1 张时可点）

**关键设计点**：
- **默认支持多图** —— 用户可选 1 张或多张，不需要切换"一份/多份"模式
- 多张图都作为**同一份报告的多页**处理（一份血常规可能 2-3 页）
- **[需确认]**：如果用户一次性想录入多份独立报告（如 5 份陈年报告），是否需要特殊流程？我们之前讨论说默认就支持多图，不区分

### 6.2 步骤 2：识别中

- 全屏 loading：进度条 + "AI 正在识别第 1/3 张..."
- 失败：错误提示 + 重试 / 手动录入

### 6.3 步骤 3：识别结果确认 — `pages/upload/confirm`

- 顶部：识别出来的报告基本信息（医院 / 日期 / 类型，用户可编辑）
- 中部：识别的指标列表（每行可编辑数值 / 标记为"识别错误"）
- 底部：保存按钮 → 写入后端 → 跳到报告详情页

**[需确认]**：

- OCR 识别失败率预期？
- 如果识别完全失败，是否提供"手动录入"作为兜底？
- 用户可以手动添加 OCR 漏掉的指标行吗？

## ⚠ 一级问题（影响产品形态）

### Q1. AI 解读功能是否做？v1.0 还是 v1.1？

PRD 提到"AI 自动解读"，但实现成本和合规风险都比较高。
- 选项 A：v1.0 不做，先专注上传 + 趋势 + 提醒（核心痛点）
- 选项 B：v1.0 做简单的异常项 highlight（不写解读文字，只标红）
- 选项 C：v1.0 做完整 AI 解读（调用 LLM），但要严格加"非医疗建议"声明

**✅ 最终决定：选项 A**

v1.0 不做任何 AI 解读，只做基础的异常项视觉标识（偏高标红、偏低标蓝、加 ↑/↓ 箭头）。
后续拿到医疗资质后，在 v1.1+ 再考虑 LLM 解读。

### Q2. 公益项目主体是谁？医疗类目资质如何？

微信小程序医疗类目审核严，必须主体合规。如果主体没有医疗资质，可能要：
- 挂靠医疗机构 / 公益基金会
- 或者降级为"健康管理工具"类目（功能要相应调整文案）

**✅ 最终决定：分两阶段**

- **Phase 1（内测）**：个人开发者主体，类目走"工具 - 实用工具"，仅邀请制访问，应用名暂时不用医疗类词汇（可叫"健康记录助手"等），不对外推广。
- **Phase 2（正式发布）**：联系基金会，用基金会主体重新注册小程序账号，类目升级为"健康管理"。

**开发阶段需要注意（避免 Phase 2 迁移困难）**：

- 数据所有权归用户本人，用户协议明示主体变更时数据可迁移
- 技术上避免绑死特定云厂商；数据库导出方案要简单
- 域名不绑死在个人名下
- 即使内测，用户协议 + 隐私政策也按正式版本写
- 内测开始时就提前和基金会沟通主体承接、数据存储合规、品牌要求等

### Q3. 是否支持子女代为管理父母账号？

如果支持：
- 数据模型需要加 `caregiverRelation` 关系
- 一个用户档案可被多个 caregiver 访问
- 需要授权 + 解除授权流程
- 隐私层面要明确"数据所有权属患者本人"

如果不支持，老人不会用微信的情况下数据就进不来。**[强烈建议至少做"家属代录"模式]**

**✅ 最终决定：方案 B — 单向代管理**

v1.0 实现"一个微信账号可以管理多个档案"：

- 用户用自己的微信账号登录，可以创建 N 个档案（自己的 + 任意数量亲属的）
- 档案完全归创建者控制，老人本人没有独立账号
- 顶部"档案切换器"切换当前管理的档案

**数据模型影响**：

- `User` 表只存登录信息（openid、token）
- 新增 `Profile` 表，存档案数据（病种、用药、姓名等）
- `User : Profile = 1 : N`
- 所有 `Report` / `RecheckPlan` / `Metric` 都归属到 `Profile` 而非 `User`

**v1.0 不做**：

- 老人独立账号 + 子女协管
- 多人共同编辑同一档案
- 操作日志记录"谁改的"

**v1.1+ 演进路径**：

- 给 `Profile` 加 `caregivers: User[]` 关系，支持多人协管
- 加权限层（owner / editor / viewer）
- 加邀请码流程

## 🟡 二级问题（影响交互）

### Q4. 关注指标的逻辑

首页"关注指标"横滑卡 + 健康数据"需要关注"，两者关系：
- 选项 A：合并 — 只有"需要关注"，由系统判定异常 + 最近常看的综合
- 选项 B：分开 — "关注"是用户手动收藏，"需要关注"是系统判定异常
- 选项 C：分开 — "关注"是用户手动 + 系统智能推荐混合

**✅ 最终决定：方案 B — 两个区块语义分开**

- **"需要关注"**（健康数据 Tab 顶部）：系统自动判定异常的指标，用户无法增删
- **"关注指标"**（首页横滑）：用户手动收藏的常看指标
  - **添加入口 A**：指标详情页 NavBar 右上的"☆/★"按钮 — 看完趋势顺手收藏
  - **添加入口 C**：首页"关注指标"右上"管理 ›" → 复用 ⑤ B 切换档案弹层 UI，列出所有指标可勾选
  - 上限 8 个，超过则提示先移除再添加
- 数据层面：`UserMetricSnapshot.isPinned` 字段即用户收藏标记；异常判定不依赖该字段

### Q5. 复查"完成"如何标记？

线框稿里没明确，文档里我列了 3 个方案：
- A：用户勾完待办 → 点"标记为已完成"
- B：到日期当天自动迁移到已完成
- C：每条计划上有"完成"按钮
- D：勾完待办自动完成（无需再点按钮）

**✅ 最终决定：方案 A**

- 待办全部勾完后，主页"下次复查"卡片底部出现大按钮"标记为已完成"
- 用户点击 → 二次确认 modal → 计划状态 `done` → 移到底部"已完成"折叠区
- 待办未全部勾完时，按钮不显示（避免误操作）
- 不做自动迁移、不做日期驱动

### Q6. 复查"之后还有"列表的点击行为

- 选项 A：跳到独立的"该计划详情页"
- 选项 B：替换主页显示的"下次复查 + 待办"为这条计划
- 选项 C：只读，不可点击

我倾向 B（不增加新页面，但要明确"切换计划"的视觉提示）。

**✅ 最终决定：方案 A — 独立计划详情页**

新增 `pages/recheck/detail?planId={id}` 页面，包含：

1. **基本信息**（可编辑）：检查类型 / 日期 / 时段 / 医院 / 科室 / 医生
2. **倒计时徽章**：居中展示"X 天后"
3. **待办事项**（核心交互）：勾选 / 添加 / 编辑 / 删除
4. **提醒配置**：提前 3 天 / 1 天 / 当天 三个开关
5. **危险操作**：取消此次复查 / 删除此计划

**主页和详情页的分工**：

- 主页 = 下次复查的快捷面板 + 其他计划的索引
  - 勾"下次复查"的待办（最高频）
  - 看"之后还有"列表
  - 点"标记为已完成"（仅最近一条）
- 详情页 = 任何一条计划的完整编辑器
  - 编辑基本信息
  - 添加 / 删除 / 编辑待办
  - 调整提醒配置
  - 取消 / 删除计划

### Q7. 上传流程的页面是否要画线框稿？

PRD 提到 3 步流程（拍照→识别→确认），但我们还没画。要不要补 3 张线框稿？建议补，否则开发会自由发挥。

**✅ 最终决定：6 张线框稿（含多页合并 + 冲突处理）**

**核心设计**：

1. **拍照 / 相册保留两个独立入口**（不调用合并的原生弹窗）
   - 兼容性更好，入口大、视觉清晰
   - 技术上分别调 `wx.chooseMedia({sourceType: ['camera']})` 和 `wx.chooseMedia({sourceType: ['album']})`

2. **多张图分组**：
   - 默认每张图 = 1 份独立报告
   - 用户主动点"合并多页 ⇆"进入多选模式，按拍摄顺序点击属于同一份的图
   - 选中顺序 = 页面顺序（用于 OCR 拼接）
   - 4 种情形全覆盖：
     - 单张：直接识别
     - 多张独立：默认不合并
     - 多张同一份：合并为 1 组
     - 混合：分别选择哪些合并

3. **OCR 后的合并 + 去重**（后端）：
   - 同一组内的图依次 OCR
   - 按 metricKey 去重：同值静默去重，不同值标记 conflict
   - 页面边界的重复数据自动处理

4. **冲突处理**：
   - 合并后产生冲突的报告卡片显示橙色提示条
   - 点"处理"进入冲突解决页：每个冲突指标单选保留哪个值
   - 可选"都不要 · 删除此项"

5. **多类别报告的科学分类存储**：
   - 一份"综合生化"报告可能含血常规 + 肝功能 + 肾功能指标
   - 这些指标各自的 category 由 Metric 定义表决定（不继承自报告类型）
   - 在"按指标"视图自动分配到对应主题下

**6 张线框稿**：
- A · 选图（默认 · 含已分组）
- B · 合并多页（多选模式）
- C · 放大预览（黑底浮层）
- D · AI 识别中（进度条）
- E · 确认 · 多份报告概览
- F · 处理重复识别（冲突）

## 🟢 三级问题（影响细节）

### Q9. 趋势文字算法

"持续上升 / 略上升 / 平稳 / 略下降 / 持续下降"怎么算？

**📝 建议默认值（开发可直接采用，特殊情况找产品确认）**：

```
取最近 3 次值 v1, v2, v3
计算 delta = (v3 - v1) / 参考范围 * 100
- delta > 15% → 持续上升 / 下降
- 5% < delta ≤ 15% → 略上升 / 下降
- |delta| ≤ 5% → 平稳
```

- 只有1 个数据点：显示"首次记录"
- 只有 2 个数据点：按上述公式算 delta = (v2 - v1) / 参考范围 * 100
- 定性型指标（阳性/阴性）：不显示趋势文字

之前砍掉了用户自定义，默认 T-3 / T-1 / T-0 三次。要不要保留为产品决策不可调？

**📝 建议默认值**：默认 T-3 / T-1 / T-0 三次，**不开放用户调整**。复查详情页（recheck/detail）有3 个开关可关闭单项提醒，但不能加新的时间点。
